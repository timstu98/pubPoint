# Project Documentation

This directory is the repository’s durable context for product direction, architectural decisions, implementation guidance, and research. Prefer these documents over external planning notes when working on the project.

Keep each fact or decision canonical in one document. Use links between documents instead of repeating the same guidance in multiple places.

## Where information belongs

- [`development/ai-workflow.md`](development/ai-workflow.md) - repeatable ticket exploration, implementation, review, and handoff workflow.
- [`product.md`](product.md) — product vision, MVP scope, and requirements.
- [`decisions/`](decisions/) — durable choices and the reasoning behind them.
- [`development/`](development/) — implementation context, API and backend guidance, database notes, and supporting research.
- [`algorithms/`](algorithms/) — algorithm-specific implementation notes. Algorithm choices themselves belong in [`decisions/`](decisions/).
- [`images/`](images/) — documentation assets.
